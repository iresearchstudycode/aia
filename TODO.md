## Known Limitations (Accepted Trade-offs)

- **In-memory auth state** — brute-force lockout counters and TOTP replay protection are stored in process memory. Restarting `vpal-auth` clears this state, giving an attacker a fresh attempt window within the 90-second TOTP validity period. Accepted trade-off for a local 1–5-user deployment; documented in `README.md`. Mitigated by adding a persistent backing store (Redis, SQLite) if the threat model requires it.
- **VoiceBox has no cancel signal for a fresh generation** — a *fresh* synthesis is played by Voicebox itself through the host's speakers with no stop/onend callback back to this page, so the "stop speaking" toolbar button and per-message speak-button toggle can't interrupt it; it plays to completion on the host regardless. (A **cached** repeat *can* be stopped — it's replayed entirely by this page via a normal `<audio>` element.) Would need a `voicebox.stop`-equivalent endpoint to close for fresh generations too.
- **VoiceBox has no authentication of its own** — any client with network access to its local port can trigger speech or read past generations, so `/voicebox/speak` and `/voicebox/audio/{id}` rely entirely on VPAL's own session gate (`auth_request`) and Nginx rate limiting for protection, not on any credential Voicebox itself checks. Accepted trade-off for a local-only, loopback-bound deployment.
- **KaTeX requires `style-src 'unsafe-inline'`** — it positions glyphs (fraction bars, radicals, sub/superscripts) via computed inline `style` attributes on the spans it generates; there's no CSS-class-only way to do this, and it's inherent to how KaTeX (and MathJax's CommonHTML output) achieve pixel-perfect typesetting without native browser math layout support. `script-src` is untouched (no inline/eval anywhere); residual risk of the `style-src` exception is bounded by the rest of the CSP (`default-src 'self'`, `connect-src 'self'`, no external hosts in `img-src`), so an inline style still can't exfiltrate data or load an external resource.
- **TTS doesn't read LaTeX aloud in spoken-word form** — `stripMarkdownForSpeech()` strips LaTeX delimiters/markdown formatting for cleaner speech, but doesn't translate math into spoken English (e.g. `\frac{1}{2}` is read as literal characters, not "one half"). Both TTS engines (Browser and VoiceBox) are affected equally; translating LaTeX to natural speech is a materially harder problem than typesetting it and was out of scope here.
- **`protectLatexDelimiters()` only protects backslash + `( ) [ ] { } \`** — not the full CommonMark escapable-punctuation set (e.g. `\&`, used for column alignment in `align`/`matrix` environments, is not protected and will still lose its backslash to markdown). Narrower than a byte-perfect fix on purpose: broadening it risks changing the rendered output for genuine non-LaTeX uses of backslash-escaped punctuation in prose (e.g. someone deliberately writing `\%` for a literal `%`). Would need revisiting if multi-row matrix/align environments turn out to be common in practice.
- **Generation cache is exact-match only, in-memory, unbounded by time** — a cache hit requires byte-identical text and profile; no fuzzy/semantic matching. Cache is cleared on `voicebox-proxy` restart and capped at 200 entries (LRU eviction) with no TTL, so a stale entry can in principle outlive its underlying Voicebox history entry (rare in practice, and the failure mode is just a 404 on replay, not incorrect audio).
- **Attached documents are truncated, not chunked/retrieved** — this is simple context-stuffing (the first `MAX_DOCUMENT_TEXT_CHARS` of extracted text, folded whole into one message), not a real RAG pipeline with embeddings/chunking/retrieval. A document longer than the truncation budget will have its tail silently unavailable to the model (a toast notes when truncation happens, but the model itself has no way to say "the answer might be further in the document — it was cut off"). Would need a proper retrieval step (chunk + embed + similarity search) to scale beyond a truncation budget.
- **Scanned/image-only and encrypted PDFs are rejected outright** — `doc-extract` has no OCR fallback (a scanned PDF parses successfully but yields zero extractable text, which is reported as an error rather than silently attaching nothing) and no password-prompt flow for encrypted PDFs. Accepted scope boundary; both would need a materially different extraction pipeline (Tesseract for OCR, a password-input UI for encrypted files).
- **Document text counts against context on every subsequent turn** — like images, once a document is attached to a message, its (possibly 28,000-character) extracted text becomes a permanent part of `conversationHistory` and is resent to Ollama on every following turn, not just the one where it was attached. `MAX_HISTORY_MESSAGES` eventually trims it once enough turns have passed, but a long document early in a long conversation makes every reply slower/more expensive in the meantime — the same trade-off the codebase already accepts for attached images.
